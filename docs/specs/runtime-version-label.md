# 執行版次標籤

## Problem Statement

部署端使用固定的 Python 檔名，無法從執行視窗或日誌可靠判斷是否已覆蓋最新程式。這使訊息擷取與 Telegram 轉發的問題難以對應到實際執行版本。

## Solution

程式以人工遞增的 `vYYYY.MM.DD.N` 版次作為唯一識別，並在執行視窗、啟動系統日誌、CSV 與網路診斷檔中清楚寫出。程式檔名保持固定。

## User Stories

1. 作為部署者，我希望啟動程式時立即看見版次，以確認遠端已套用正確版本。
2. 作為除錯者，我希望每份輸出檔都可追溯到產生它的程式版次。
3. 作為維護者，我希望不必更改固定檔名即可發佈新版。
4. 作為維護者，我希望每次程式變更都能手動遞增版次，讓版次可重現且可溝通。

## Implementation Decisions

- 使用一個程式內常數作為唯一版次來源。
- 目前版次為 `v2026.07.27.1`，後續變更由維護者手動遞增。
- 既有視窗標題、系統日誌與輸出檔建立流程是唯一測試及呈現接縫。
- 版次會以檔頭或啟動紀錄方式寫入輸出，避免干擾既有 CSV 資料列格式。

## Testing Decisions

- 啟動時必須能在視窗標題與系統日誌讀到同一版次。
- 每種新建立的輸出檔必須能讀到同一版次。
- 測試只驗證使用者可見的識別結果，不依賴內部常數位置。

## Out of Scope

- 自動依時間、Git 或檔案雜湊產生版次。
- 變更遠端程式檔名。
- 建置或發佈自動化。

## Further Notes

- 版次僅用於部署辨識與問題回報。
