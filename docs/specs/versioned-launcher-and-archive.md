# 版次化啟動與歷史歸檔

## Problem Statement

監控程式需要以包含版次的檔名部署，但現有啟動腳本固定指定舊檔名。舊版程式也會留在執行目錄，容易被誤啟動或使部署狀態難以辨識。

## Solution

每個新版程式使用 `fpc_watch_ui_login_telegram_vYYYY.MM.DD.N.py` 檔名。啟動腳本依檔名版次選出最新版、將所有其他同名前綴程式安全搬至 `History/`，然後執行最新版。沒有任何有效版次檔案時，腳本輸出錯誤並結束。

## User Stories

1. 作為部署者，我希望新版檔名直接包含版次，以辨識已上傳內容。
2. 作為部署者，我希望啟動指令自動選出最新版，不必每次手改檔名。
3. 作為部署者，我希望舊版自動保留在歷史目錄，而不干擾最新版啟動。
4. 作為維護者，我希望歷史檔不被覆蓋，以便必要時追溯或回復。
5. 作為操作人員，我希望沒有有效新版時腳本明確失敗，而不是誤跑舊版。

## Implementation Decisions

- 程式檔名的版次格式與執行端版次標籤一致。
- 啟動腳本以版次排序選取最新有效檔案，不使用檔案修改時間。
- 歸檔範圍包含舊格式與舊版次的同名前綴 Python 檔案；最新有效版本保留。
- 歷史目錄同名衝突時，歸檔檔名增加時間識別，絕不覆寫。
- 缺少有效版次檔案是啟動錯誤，不允許使用舊格式檔案回退。

## Testing Decisions

- 測試檔名版次排序會選出最高版次。
- 測試舊格式與舊版次檔案都會被歸檔，最新版不會被移動。
- 測試沒有有效版次檔案時腳本以非零狀態結束並顯示錯誤。

## Out of Scope

- 自動下載、上傳或遠端發佈程式。
- 自動清除歷史版本。
- 對正在執行的舊程序進行停止或重啟。

## Further Notes

- 執行端仍以程式內版次標籤與系統日誌驗證實際執行版本。
