# 未開啟群組的最後訊息補抓

## Problem Statement

目前監控程式只能從聊天側欄取得截斷的預覽文字。當未讀群組沒有被開啟時，程式可能找不到該群組的完整訊息內容，最終把預覽或省略號內容寫入通知、Telegram 與 CSV。

## Solution

當側欄未讀群組出現或更新時，程式沿用現有登入瀏覽器工作階段，從聊天服務主動請求該群組最新一則訊息。補抓不會點擊、選取或切換任何聊天群組 UI。取得完整內容後，程式將其送進既有的訊息處理流程；若無法確認端點或回應內容，程式只保留側欄訊號並輸出可診斷資料，不把截斷預覽偽裝為完整內容。

## User Stories

1. 作為監控者，我希望未讀群組沒有被開啟時仍能取得最後一則訊息的完整內容，讓通知不含省略號截斷。
2. 作為監控者，我希望補抓不改變目前瀏覽器所顯示的聊天群組，讓監控不干擾人工操作。
3. 作為監控者，我希望每個未讀群組只補抓最新一則訊息，讓請求量保持最小。
4. 作為監控者，我希望完整內容能沿用目前的群組訊息畫面、CSV、浮動通知與 Telegram 處理流程。
5. 作為監控者，我希望端點或資料格式變動時可查看診斷紀錄，快速修正而不誤送側欄摘要。
6. 作為監控者，我希望相同最後訊息不會因輪詢重複通知或重複寫入 CSV。

## Implementation Decisions

- 側欄預覽只觸發補抓，不作為完整訊息內容的替代品。
- 補抓使用現有 Playwright 瀏覽器 context 的認證狀態，不另行管理 token、cookie 或第二次登入。
- 從既有瀏覽器網路流量辨識群組識別、訊息端點、請求格式及回應資料結構，再以相同 context 請求單筆最新訊息。
- 將已解析的完整訊息送入現有訊息佇列，維持既有的去重、附件、CSV、通知與 Telegram 行為。
- 端點辨識或補抓失敗時留下結構化診斷資訊；不轉發不完整的側欄預覽。

## Testing Decisions

- 好的測試只驗證可觀察行為：未開啟群組時收到完整最後訊息、聊天 UI 未切換、失敗時不送出截斷內容、重複事件不重複處理。
- 以側欄未讀事件進入既有訊息佇列作為最高層接縫；請求建構與回應解析則以可替換的資料來源測試。
- 使用含有長文字的群組（如側欄顯示省略號的情境）驗證完整內容會出現在輸出中。

## Out of Scope

- 回補整段未讀歷史或全部聊天紀錄。
- 讀取沒有未讀徽章的群組。
- 以點擊、切換或打開群組 UI 取得訊息。

## Further Notes

- 「最後一則訊息」指伺服器端最新訊息，不是側欄的視覺摘要。
